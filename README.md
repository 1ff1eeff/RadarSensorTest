# АИСТ-РУ

**Автоматизированный испытательный стенд для проверки радарных уровнемеров УР-Х.**

Приложение объединяет рабочее место оператора, обмен с измерительными модулями и датчиками, диагностику, ведение реестра моделей и формирование протоколов испытаний. Интерфейс работает в собственном окне на базе Microsoft Edge WebView2, а вся логика и локальный HTTP-сервер находятся в одном Windows-приложении.

> Программа предназначена для работы в закрытом контуре: интерфейс, стили, шрифты и скрипты поставляются локально. Для работы самого стенда интернет не требуется.

## Возможности

### Испытание уровнемеров

- выбор модели уровнемера из реестра с расшифровкой исполнения, диапазона, выходных сигналов, температурного исполнения, присоединения и взрывозащиты;
- ввод заводского номера датчика и заводского номера ОВЕН;
- запуск и остановка испытания, в том числе автоматический запуск по дискретному входу `DI2`;
- повторные измерения с настраиваемым количеством тестов и паузой;
- таблица параметров с эталонными, минимальными, максимальными, измеренными значениями и отклонением;
- итоговый вердикт «Годен» / «Не годен» и пояснение результата;
- защита от запуска при незаполненных контрольных значениях или нулевых допусках;
- формирование протокола испытаний по Excel-шаблону и сохранение в выбранную папку.

### Обмен с оборудованием

- **Modbus TCP**: аналоговый модуль МВ 210-101 и дискретный модуль МК 210-301;
- **RS-485 / Modbus RTU**: датчики на шинах B1/B2, включая карты WSR550 и PWRD86/86A;
- **HART**: показания АС6-Д, параметры датчика и команды PWRD, включая команду 135;
- настраиваемые COM-порты, скорости, чётность, размер слова и стоп-биты;
- настраиваемые регистры, адреса и порядок байт `float`/`int16`;
- контроль состояния модулей и шин в главном окне и окне диагностики;
- управление дискретными выходами `DO1…DO7` из диагностики.

### Диагностика

- непрерывный опрос измерительных каналов;
- карточки параметров МВ 210-101, МК 210-301, датчика на B2 и АС6-Д;
- отображение уровня, высоты пустоты, расстояния, температуры и тока петли;
- график расстояния по всей истории замера;
- масштабирование, прокрутка истории и режим LIVE;
- сохранение положения, масштаба и режима просмотра между открытиями окна;
- отдельные журналы RS-485 и HART для разбора обмена и ошибок.

### Настройки и справочники

- сетевые адреса модулей Modbus TCP;
- параметры COM-портов HART и RS-485;
- карты регистров МВ, МК, АС4-М, УР и УРМ;
- параметры установки уровнемеров и выдержка после записи;
- контрольное расстояние и пороги отклонений;
- импорт и экспорт конфигурации, сброс к значениям по умолчанию;
- реестр моделей датчиков в `models.json`: добавление, удаление и просмотр;
- единый словарь сообщений `messages.json`, изменения в котором видны без пересборки;
- справка оператора и инженера из меню и по клавише `F1`.

### Интерфейс

- полноэкранное главное окно и модальные дочерние окна;
- защита служебных окон паролем, заданным заказчиком;
- отключённые браузерные меню, горячие клавиши разработчика и строка состояния WebView2;
- тёмная промышленная тема интерфейса;
- локальная работа без CDN и внешних запросов.

## Системные требования

### Для запуска

- Windows 10 или Windows 11, **x64**;
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) (Evergreen Runtime);
- .NET 10 Desktop Runtime — если используется framework-dependent сборка;
- свободный локальный порт **5000**;
- разрешение экрана: рекомендуется 1920×1080 или выше;
- для полноценной проверки — стенд с модулями МВ 210-101, МК 210-301, преобразователем АС4-М/АС6-Д и проверяемым уровнемером.

Приложение можно открыть и без подключённого оборудования: интерфейс запустится, а состояния модулей будут отображаться как «Нет». Испытание без необходимых модулей и датчика не проводится.

### Для сборки

- [.NET 10 SDK](https://dotnet.microsoft.com/download);
- Windows PowerShell 5.1 или PowerShell 7 — для скрипта компактной публикации;
- доступ к NuGet при первой сборке/восстановлении пакетов;
- Visual Studio 2022 с workload «.NET desktop development» — опционально, для отладки.

Проект использует Windows Forms и WebView2, поэтому **Linux и macOS не поддерживаются**.

## Установка и запуск

### 1. Клонирование

```powershell
git clone <URL-репозитория>
cd <папка-репозитория>
```

### 2. Восстановление и сборка

```powershell
dotnet restore "АИСТ-РУ.slnx"
dotnet build "АИСТ-РУ.slnx"
```

Если приложение уже запущено, закройте его перед пересборкой: работающий `АИСТ-РУ.exe` удерживает файлы выходной папки.

### 3. Запуск

После сборки запустите:

```powershell
Start-Process ".\АИСТ-РУ\bin\Debug\net10.0-windows\АИСТ-РУ.exe"
```

Либо откройте `АИСТ-РУ.slnx` в Visual Studio, выберите конфигурацию `Debug`/`x64` и запустите проект.

При старте приложение:

1. поднимает локальный Kestrel-сервер на `http://localhost:5000`;
2. открывает главное окно с интерфейсом WebView2;
3. запускает фоновый опрос оборудования.

Порт 5000 слушается только на loopback-интерфейсе. API стенда не предназначен для удалённого доступа из сети.

### 4. Проверка сборки

```powershell
dotnet test "АИСТ-РУ.UnitTests/АИСТ-РУ.UnitTests.csproj"
```

Перед API-тестами закройте запущенный экземпляр приложения:

```powershell
dotnet test "АИСТ-РУ.ApiTests/АИСТ-РУ.csproj"
```

`ApiTests` поднимает собственный экземпляр стенда и проверяет HTTP-контракты и статические страницы.

## Публикация

### Компактная поставка

Скрипт публикует Release-сборку в `publish-compact` и удаляет сторонние NuGet-файлы. При первом запуске приложение проверяет `АИСТ-РУ.deps.json` и предлагает докачать недостающие библиотеки с nuget.org.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-compact.ps1
```

Результат: папка `publish-compact`. Для установки её нужно распаковать целиком: рядом с `АИСТ-РУ.exe` должны находиться `wwwroot`, `Help`, `settings.json`, `models.json`, `grid_data.json`, `messages.json` и шаблон протокола.

Если нужна обычная полная публикация без удаления NuGet-файлов:

```powershell
dotnet publish "АИСТ-РУ/АИСТ-РУ.csproj" -c Release -o publish -p:SqueezeCompactTrim=true
```

### Первый запуск после компактной публикации

- при первом старте может потребоваться интернет для докачки библиотек;
- для неинтерактивной проверки предусмотрены ключи `--deps-scan` и `--deps-install`; они пишут отчёт `deps-report.txt` рядом с exe;
- после успешной докачки библиотеки лежат рядом с программой и повторный интернет не нужен.

## Первый запуск и настройка

1. Подключите модули и преобразователи к компьютеру и проверьте питание.
2. Откройте **Файл → Настройки…**.
3. Укажите:
   - IP-адреса и порты МВ 210-101 и МК 210-301;
   - COM-порты, скорости и параметры кадров HART/RS-485;
   - регистры и порядок байт для используемых карт;
   - параметры установки уровнемера;
   - контрольное расстояние и пороги отклонений;
   - количество тестов, паузу и папку для протоколов.
4. Сохраните настройки. Они записываются в `settings.json` рядом с программой.
5. Выберите модель датчика на главном экране и проверьте состояния шин в нижней строке.
6. Подключите проверяемый датчик и запустите испытание кнопкой **«НАЧАТЬ ТЕСТ»** или клавишей `Enter`.

Служебные окна «Настройки», «Диагностика» и «Создание модели датчика» защищены паролем, заданным заказчиком.

## Как проходит испытание

1. Оператор выбирает модель и вводит заводские номера.
2. Приложение проверяет заполненность уставок и допусков.
3. В датчик записываются параметры установки, затем выдерживается настроенная пауза.
4. Выполняется заданное число измерений по доступным каналам.
5. Значения сравниваются с эталоном и допусками.
6. Формируется вердикт, карточка результата и протокол.
7. Протокол сохраняется в выбранную папку; ход выполнения и ошибки отражаются в интерфейсе и журналах.

Испытание можно остановить кнопкой **«ОСТАНОВИТЬ ТЕСТ»**. Повторный запуск во время активного испытания игнорируется. Если открыта диагностика, запуск нового испытания и повторное открытие COM-портов блокируются, чтобы не повредить обмен.

## Данные и файлы

Рядом с исполняемым файлом размещаются рабочие данные:

| Файл/папка | Назначение |
|---|---|
| `settings.json` | настройки стенда |
| `models.json` | реестр моделей уровнемеров |
| `grid_data.json` | контрольные значения и границы таблицы допусков |
| `messages.json` | словарь сообщений интерфейса |
| `Help\` | инструкции оператора и инженера в `.docx` |
| `Шаблон ПСИ.xls` | шаблон протокола испытаний |
| `Результаты\` | папка протоколов, задаётся в настройках |
| `rs485_write.log` | журнал записи установок по RS-485 |
| `hart_debug.log` | журнал ошибок HART, создаётся при сбоях |

Файлы настроек и реестра изменяются во время работы. При обновлении программы не заменяйте их исходными версиями без необходимости.

## Ограничения

- Поддерживается только Windows; приложение использует Windows Forms, COM-порты и WebView2.
- Локальный сервер слушает только `localhost:5000`; удалённое управление стендом не предусмотрено.
- Одновременно должен работать только один экземпляр приложения.
- Полное испытание требует подключённого оборудования и корректно заполненных настроек.
- Для доступа к служебным окнам требуется пароль, заданный заказчиком.
- В интерфейсе есть небольшая пасхалка с мини-играми; она не связана с испытанием и не влияет на результаты.
